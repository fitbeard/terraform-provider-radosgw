# radosgw_iam_account_user

Manages an IAM user **within a RadosGW account**, using the S3/IAM API (`CreateUser`) rather than the cluster-wide Admin Ops API.

Unlike `radosgw_iam_user` (which requires the cluster-wide `users` admin capability), this resource is created through the account's IAM data plane, so it can be managed by an **account root user** — or any account member holding an IAM policy that grants `iam:CreateUser` — **without any admin capabilities**. Configure the provider (typically an aliased instance) with the account root's credentials.

~> **`radosgw_iam_user` vs `radosgw_iam_account_user`:** use `radosgw_iam_user` (Admin Ops API) when you have admin caps and need full RGW user metadata — display name, email, quotas, `op_mask`, suspension, caps, Swift subusers — including creating an account's **root** user. Use this resource for least-privilege management of member users inside an account, where only the IAM identity (name, path, ARN) is needed. The two manage **different entities**: an IAM account user has no Admin Ops metadata record. Grant it S3/IAM permissions with IAM policies, and create its credentials with `radosgw_iam_account_access_key`.

~> **Note:** RadosGW's IAM user API does not support tags or a permissions boundary, so those AWS attributes are intentionally omitted.

## Example Usage

```terraform
# A second provider authenticated as the account root user (no admin caps).
provider "radosgw" {
  alias      = "account_root"
  endpoint   = "http://rgw.example.com:7480"
  access_key = "ACCOUNTROOTACCESSKEY"
  secret_key = "accountRootSecretKey"
}

# An IAM user inside the account, created via the IAM API (least privilege).
resource "radosgw_iam_account_user" "developer" {
  provider = radosgw.account_root
  name     = "developer"
  path     = "/engineering/"

  # Remove the user's access keys and policies when destroyed.
  force_destroy = true
}
```

## Argument Reference

The following arguments are supported:


* `name` - (Required) The name of the IAM user. Can be renamed in place.


* `force_destroy` - (Optional) When `true`, destroying this resource first deletes the user's access keys, inline policies, and attached (managed) policies so the user can be removed. Without it, RadosGW refuses to delete a user that still has access keys or policies. Defaults to `false`.
* `path` - (Optional) The path for the user (an IAM path, which must begin and end with `/`). Defaults to `/`.




## Attributes Reference

The following attributes are exported:

* `arn` - The Amazon Resource Name (ARN) that identifies the user, scoped to the account (`arn:aws:iam::<account-id>:user/<path><name>`).
* `create_date` - The date and time the user was created, in RFC 3339 format.
* `unique_id` - The stable unique identifier assigned to the user by RadosGW.
* `name` - See Argument Reference above.
* `force_destroy` - See Argument Reference above.
* `path` - See Argument Reference above.
## Import

Import is supported using the following syntax:

```shell
# Import an account IAM user by its name (using account-scoped credentials)
terraform import radosgw_iam_account_user.developer "developer"
```
