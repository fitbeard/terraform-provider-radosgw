# radosgw_s3_account_public_access_block

Manages the account-wide S3 Public Access Block configuration for a RadosGW account, via the S3 Control `PutPublicAccessBlock` API. This is the RadosGW equivalent of `aws_s3_account_public_access_block`. The configuration applies to **all buckets owned by the account**; when both an account-level and a bucket-level ([`radosgw_s3_bucket_public_access_block`](s3_bucket_public_access_block)) configuration are present, the more restrictive of the two wins.

~> **Ceph version:** account-wide Public Access Block is **Ceph 21 (Umbrella) only** (added in 21.1.1; not backported to Squid or Tentacle). When the provider's `ceph_version` targets an older release this resource is rejected at plan time. Verified on Ceph 21.2.0: all four settings round-trip and are enforced (e.g. `block_public_acls` rejects `CreateBucket`/`PutBucketAcl` with a public ACL across the account's buckets).

~> **Credentials:** account-wide Public Access Block is managed by the account's **own root credentials** — the RadosGW admin user cannot set it for an account (it returns `MethodNotAllowed`), which matches AWS (an account manages its own Block Public Access). Configure the provider (typically an [aliased provider](https://developer.hashicorp.com/terraform/language/providers/configuration#alias-multiple-provider-configurations)) with the account root's `access_key`/`secret_key`, and set `account_id` to that same account.

~> **Addressing:** the AWS SDK normally addresses the S3 Control API at `<account-id>.<host>`, which needs wildcard DNS. The provider instead sends the account id in the `x-amz-account-id` header (RadosGW ignores the hostname), so no special DNS is required. The `s3control` API must be enabled on the gateway (`rgw_enable_apis` includes `s3control`, which is the default).

## Example Usage

```terraform
# Block all public access for every bucket in a RadosGW account.
#
# Account-wide Public Access Block is managed by the account's own root
# credentials (the admin user cannot set it). Configure the provider — here an
# aliased provider — to authenticate as the account root, and set account_id to
# that same account.
provider "radosgw" {
  alias      = "account_root"
  endpoint   = "http://127.0.0.1:7480"
  access_key = var.account_root_access_key
  secret_key = var.account_root_secret_key
}

resource "radosgw_s3_account_public_access_block" "example" {
  provider = radosgw.account_root

  account_id = "RGW12345678901234567"

  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
```

## Argument Reference

The following arguments are supported:


* `account_id` - (Required) The ID of the RadosGW account the configuration applies to (for example `RGW12345678901234567`).


* `block_public_acls` - (Optional) Whether RadosGW should block public ACLs for buckets in this account. When `true`, `CreateBucket`/`PutObject`/`PutBucketAcl` requests that specify a public ACL are rejected. Defaults to `false`.
* `block_public_policy` - (Optional) Whether RadosGW should block public bucket policies for buckets in this account. When `true`, `PutBucketPolicy` requests that grant public access are rejected. Defaults to `false`.
* `ignore_public_acls` - (Optional) Whether RadosGW should ignore public ACLs for buckets in this account. When `true`, any existing public ACLs on the account's buckets and objects are ignored (access is treated as private). Defaults to `false`.
* `restrict_public_buckets` - (Optional) Whether RadosGW should restrict public bucket policies for buckets in this account. When `true`, access to a bucket with a public policy is restricted to authorized users within the account. Defaults to `false`.
* `skip_destroy` - (Optional) When `true`, the public-access-block configuration is left in place on the account when this resource is destroyed (instead of being removed). Defaults to `false`.
